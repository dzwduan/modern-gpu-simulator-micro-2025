# 第 0 章：关键路径时序图（端到端）

> 本章提供三条核心执行路径的端到端时序图，帮助开发者在深入各模块前建立全局认知。

---

## 0.1 ALU 指令路径（fetch → retire）

```
  Cycle N     Cycle N+1    Cycle N+2    Cycle N+3    Cycle N+4    Cycle N+5    Cycle N+6    Cycle N+7    Cycle N+8+
┌─────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│  fetch  │→│  decode  │→│  issue   │→│ control  │→│ allocate │→│ read_rf  │→│ execute  │→│writeback │→│  retire  │
│         │ │          │ │          │ │          │ │          │ │          │ │ (N cyc)  │ │          │ │          │
└─────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘
     │            │            │            │            │            │            │            │            │
  L0I访问     trace解码     检查:         设置barrier   RF读端口     调用        FU pipeline  RF写端口     SM::
  →IBuffer    填IBuffer    stall=0?      pending      预留+FU      barrier      推进         检查+写入   instruction
  预分配槽位   entry        yield ready?  increment    latency槽位  release_     inst进入      →结果队列   _retirement
              m_valid=true  barriers ok?  →SM stack    预留         read_barrier m_pipeline   弹出        write barrier
              m_inst=pI     FU可发射?                                            _reg[]                  pending dec
                            结果队列有空?

Latch:       Latch:        Latch:        Latch:        Latch:       Latch:       Latch:       Latch:
ifetch_buf → IBuffer_Entry→ ISSUE_       → CONTROL_    → pipeline_  → read_stage → FU内部     → rf_write
             (deque)        CONTROL       ALLOCATE      read_stage   _aux_latch   pipeline     _queue
                            _latch        _latch        _latency     →FU dispatch _reg[]
                                                        _reg[N-1]    _reg
```

固定延迟 ALU 指令（如 SP/FADD）经过完整的 8 级流水线。关键特征：
- **allocate** 同时预留 RF 读端口和 FU latency 槽位
- **read_rf** 阶段会调用 `release_read_barrier()`；是否实际产生 pending decrement 取决于 guard 条件（trace/control bits/scoreboard 模式）
- **execute** 完成后结果进入 `m_regular_fixed_latency_rf_write_queue`，由 writeback 弹出
- **retire** 在 `SM::instruction_retirement()` 中产生 write barrier pending decrement

## 0.2 访存指令路径（fetch → PRT → L1D → retire）

```
Subcore 侧                          SM 共享 ldst_unit_sm 侧
─────────────                        ──────────────────────────
fetch→decode→issue→control
  │
  ▼ (variable latency, 不经 allocate/read_rf)
  FU: m_memory_unit_subcore
  (functional_unit_with_queue)
  │
  ▼ m_EX_MEM_shared_sm_reception_latch
  ┌──────────────────────────────────────────────────────────────────┐
  │ ldst_unit_sm::cycle()                                            │
  │                                                                  │
  │ 1. reception_ports[icnt_id] ──arbitration──→ issue()             │
  │    │                                                             │
  │ 2. PRT::assign_entry(inst)  ← 分配 PRT 槽位                      │
  │    │                                                             │
  │ 3. get_accesses → InterWarp Coalescing → m_next_access_to_queue  │
  │    │                                                             │
  │ 4. 路由到子流水线:                                                 │
  │    ├─ Global/Local → m_access_queue_to_l1d_preTLB[bank]          │
  │    │                 → postTLB → L1D latency queue → L1D access  │
  │    ├─ Shared      → m_access_queue_to_shmem → shmem_pipeline     │
  │    ├─ Const       → m_access_queue_to_l1c                        │
  │    ├─ Texture     → m_access_queue_to_l1t                        │
  │    └─ Bypass      → m_access_queue_to_bypass_to_l2 → ICNT        │
  │    │                                                             │
  │ 5. 完成: pending_access_logic() → PRT::solve_access()            │
  │    │     m_entries[id].decrement_num_pending_accesses_to_solve()  │
  │    │                                                             │
  │ 6. writeback 仲裁: PRT::pop_entries() → result_ports[icnt_id]    │
  └──────────────────────────────────────────────────────────────────┘
                                     │
                                     ▼
Subcore::writeback()
  → m_EX_WB_sm_shared_units_latch
  → RF 写端口检查 → SM::instruction_retirement()
```

> 注：图中 ldst_unit_sm 侧的编号表示逻辑阶段，不代表 `ldst_unit_sm::cycle()` 的单周期调用顺序；精确时序见第 7 章。

访存指令的关键特征：
- **control 阶段后直接进入 FU**，不经过 allocate/read_rf（variable latency 路径）
- **read barrier decrement 由 `functional_unit::release_read_barrier()` 触发**，调用点可能位于 `read_rf` 或 FU 内部阶段（与 FU 类型/路径相关）
- **PRT 是访存指令的核心跟踪结构**，每条指令占一个 entry，跟踪所有 pending access
- **InterWarp Coalescing** 在 access 生成后、路由到子流水线前执行合并
- **writeback 仲裁** 在 subcores 和 icnt 之间轮转

## 0.3 Wait-Barrier 同步路径

```
时间线 ──────────────────────────────────────────────────────────────→

指令 A (产生 barrier):
  issue → control_stage ──→ SM::m_pending_wait_barrier_increments (push)
                                    │
                                    ▼ SM::cycle() 尾部
                            consume increments
                            Dependency_State::action_over_wait_barrier()
                            Wait_Barrier[id].m_counter++
                                    │
  (执行中...)                        │
  read_rf/FU内部阶段 → release_read_barrier ──→ SM::m_pending_wait_barrier_decrements (push)  [READ barrier]
                                    │
  writeback → instruction_retirement ──→ SM::m_pending_wait_barrier_decrements (push) [WRITE barrier]
                                    │
                                    ▼ SM::cycle() 尾部
                            consume decrements
                            Wait_Barrier[id].m_counter--

指令 B (等待 barrier):
  issue → 检查 wait_barrier_bits (6-bit mask)
        → 对每个 set bit: Wait_Barrier[id].m_counter <= 0 ?
        → 全部满足才可发射

特殊情况:
  DEPBAR:     检查 Wait_Barrier[sb_reg].m_counter <= sb_max_allowed_val
  LDGDEPBAR:  检查 m_num_pending_ldgsts == 0 (独立计数器)

消费顺序: increments 先于 decrements（同一 cycle 内）
```

Wait-Barrier 的关键特征：
- **两阶段消费**：increment 和 decrement 都先 push 到 SM 级 pending stack，在 `SM::cycle()` 尾部统一消费
- **消费顺序固定**：同一 cycle 内 increments 先于 decrements
- **Read barrier** 的 decrement 统一由 `release_read_barrier()` 触发；调用时机取决于具体 FU 路径（`read_rf` 或 FU 内部阶段）
- **Write barrier** 在指令退休时释放
- **DEPBAR** 允许检查 counter <= 特定值（不仅仅是 0）
- **LDGDEPBAR** 使用独立的 `m_num_pending_ldgsts` 计数器，与 wait barrier 体系分离
