## 2.1 模块接口概览

### Input Ports

| 端口名 | 类型 | 宽度 | 来源 | 说明 |
|---|---|---|---|---|
| `m_EX_MEM_reception_latches_per_subcore[0..N-1]` | `register_set_uniptr*` | 1 inst/port | 各 Subcore 的 `m_memory_unit_subcore` | 访存指令从 subcore 进入 SM 共享访存单元 |
| `m_EX_MEM_reception_latches_per_subcore[N]` | `register_set_uniptr*` | 1 inst | LDGSTS 内部通路 | LDGSTS 的 store 阶段从 icnt 返回后重新进入 ldst_unit_sm |
| `m_EX_DP_shared_sm_reception_latch` | `register_set_uniptr` | 1 inst | 各 Subcore 的 `m_dp_pipeline` | DP 指令从 subcore 进入 SM 共享 DP 单元 |
| `accept_fetch_response(mem_fetch*)` | 函数调用 | - | L1I/L0_icnt | 指令 cache 响应返回 |
| `accept_ldst_unit_response(mem_fetch*)` | 函数调用 | - | ICNT/L2 | 访存响应从互连网络返回 |

### Output Ports

| 端口名 | 类型 | 宽度 | 去向 | 说明 |
|---|---|---|---|---|
| `m_EX_WB_sm_shared_units_subcore_latches[0..N-1]` | `register_set_uniptr*` | 1 inst/port | 各 Subcore 的 `m_EX_WB_sm_shared_units_latch` | SM 共享单元完成后写回各 subcore |
| `m_icnt->push(mem_fetch*)` | 函数调用 | - | 互连网络 | 访存请求发往 L2/DRAM |

### 关键配置参数

| 参数 | 说明 |
|---|---|
| `num_subcores` | Subcore 数量（决定 reception/result port 数量） |
| `max_warps_per_shader` | SM 内最大 warp 数 |
| `max_cta_per_core` | SM 内最大 CTA 数 |
| `max_barriers_per_cta` | 每 CTA 最大 programmer barrier 数 |

## 2.2 SM 类结构与关键成员

```
SM (继承 core_t, shader_core_ctx_wrapper)
│
├── Subcore 管理
│   ├── m_subcores: vector<Subcore*>          // 大小 = num_subcores
│   └── m_physical_warp: vector<shd_warp_t*>  // 大小 = max_warps_per_shader
│
├── SM 级共享执行资源
│   ├── m_ldst_unit_shared_of_sm: ldst_unit_sm*
│   │   ├── reception_ports: num_subcores + 1 个输入端口
│   │   └── result_ports: num_subcores 个输出端口
│   └── m_shared_dp_unit: functional_unit_shared_sm_part*
│       ├── reception_ports: 指向各 subcore 的 DP reception latch
│       └── result_ports: 指向各 subcore 的 WB latch
│
├── 指令供给
│   ├── m_L0_icnt: L0_icnt*                          // L0 ↔ L1I 互连
│   └── m_L1I_L1_half_C_cache: shared_ptr<read_only_cache>  // 共享 L1I
│
├── Barrier 管理
│   ├── m_barriers: barrier_set_t                     // programmer barrier
│   ├── m_pending_wait_barrier_increments: stack<Wait_Barrier_Entry_Modifier>
│   └── m_pending_wait_barrier_decrements: stack<Wait_Barrier_Entry_Modifier>
│
├── Scoreboard（本路径下不参与 issue/retire 判定）
│   ├── m_scoreboard: shared_ptr<Scoreboard>          // RAW/WAW
│   └── m_scoreboard_WAR: shared_ptr<Scoreboard_reads> // WAR
│
└── 调度控制
    └── m_num_cycles_to_wait_to_dispatch_another_inst_from_subcore_to_sm_shared_pipeline: unsigned int
```

## 2.3 SM::cycle() 执行顺序与语义

`SM::cycle()` 是每个时钟周期的顶层入口，执行顺序如下：

```
SM::cycle() {
  1. m_L0_icnt->cycle()                    // L0 ↔ L1 互连推进
  2. m_L1I_L1_half_C_cache->cycle()        // L1I cache 推进
  3. m_shared_dp_unit->cycle()             // SM 共享 DP 单元推进
  4. m_ldst_unit_shared_of_sm->cycle()     // SM 共享访存单元推进
  5. for each subcore:
       subcore->cycle()                    // 各 Subcore 流水线推进
  6. consume_pending_wait_barrier_actions(m_pending_wait_barrier_increments)   // 消费 barrier increments
  7. consume_pending_wait_barrier_actions(m_pending_wait_barrier_decrements)   // 消费 barrier decrements
  8. m_num_cycles_to_wait_to_dispatch_another_inst_from_subcore_to_sm_shared_pipeline--  // 递减共享单元调度间隔
}
```

执行顺序的设计意图：
- **步骤 1-2 先于 5**：指令互连与 L1I 响应先推进，确保 subcore fetch 阶段能看到最新的 cache 状态
- **步骤 3-4 先于 5**：共享执行资源先推进，腾出 result port 供 subcore writeback 消费
- **步骤 6 先于 7**：同一 cycle 内 increment 先于 decrement 消费，保证 barrier 计数器的正确性
- **步骤 5 中各 subcore 顺序执行**：subcore 之间通过共享资源（ldst_unit_sm、shared_dp_unit）隐式交互

## 2.4 指令退休流程

`SM::instruction_retirement(warp_inst_t* instruction)` 在 Subcore writeback 阶段被调用。

在 True-Path 下的执行逻辑：

```cpp
void SM::instruction_retirement(warp_inst_t* instruction) {
  warp_id = instruction->warp_id();

  // True-Path: 不走传统 scoreboard 释放
  // guard: !(use_traditional_scoreboarding || is_remodeling_scoreboarding_enabled || !is_trace_mode)

  // 1. Write barrier decrement
  if (instruction 有 new_write_barrier) {
    add_pending_wait_barrier_decrement(instruction, WRITE_WAIT_BARRIER, barrier_id);
  }

  // 2. LDGSTS pending 计数递减
  if (instruction->m_is_ldgsts) {
    m_physical_warp[warp_id]->get_dependency_state()->decrease_num_pending_ldgsts();
  }

  // 3. 通用退休
  m_physical_warp[warp_id]->dec_inst_in_pipeline();
  warp_inst_complete(*instruction);
  instruction->clear();
}
```

关键点：
- Write barrier decrement 不是立即生效，而是 push 到 `m_pending_wait_barrier_decrements` stack
- LDGSTS 的 pending 计数递减是立即生效的（直接调用 `decrease_num_pending_ldgsts()`）
- `dec_inst_in_pipeline()` 递减 warp 的 in-flight 指令计数

## 2.5 Wait-Barrier 消费机制

```cpp
void SM::consume_pending_wait_barrier_actions(stack<Wait_Barrier_Entry_Modifier> &actions) {
  while (!actions.empty()) {
    current_action = actions.top();
    m_physical_warp[current_action.sm_warp_id]
      ->get_dependency_state()
      ->action_over_wait_barrier(&current_action);
    actions.pop();
  }
}
```

`add_pending_wait_barrier_increment` 和 `add_pending_wait_barrier_decrement` 的调用点：

| 调用点 | 类型 | 触发条件 |
|---|---|---|
| `Subcore::control_stage()` | INCREMENT | 指令 control bits 中有 `new_read_barrier` |
| `Subcore::control_stage()` | INCREMENT | 指令 control bits 中有 `new_write_barrier` |
| `functional_unit::release_read_barrier()` | DECREMENT | variable latency 指令 dispatch 时释放 read barrier |
| `SM::instruction_retirement()` | DECREMENT | 指令退休时释放 write barrier |
